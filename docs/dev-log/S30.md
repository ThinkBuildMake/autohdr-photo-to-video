# S30 - The worker keeps a job inside 30 minutes, stops it cleanly, and cuts the passed shots to the song

**Kind:** module (M) | **Blocked by:** S01 | **Review gate:** agents
**Status:** landed by agents (no human demo). Story gate green: 554 passed, 5 skipped.

## Summary

The video is due within 30 minutes, one bad shot must not take the others down, and when the service runs out of credit nothing finished is lost. S30 builds the pieces of the worker that enforce this:
- The run deadline: no clip is requested once there is no time left for one more clip and its check.
- The stop cases: out of credit, no shot passed, and assembly failed.
- Assembly of the passed shots that were not removed, in position order, over the song.
- Comparison's recordCuts, called after a finished job.
- A test that the worker runs its startup recovery before it claims any job.

It is built against the real Jobs tables (S29). Providers, Media, Files and Comparison are stubbed or replaced at their module boundaries. Requirements: PF-1, PF-3, RL-3, CH-2. Guards: PF-1, PF-3, RL-3.

## What was built

S12 (`runner.py`) was being built in parallel, so no S12 file was touched. Pipeline owns no table, and the table-ownership gate stays green.

- `app/pipeline/run.py` (new).
  - `Run(job_id, deadline)` and `Run.for_job(job)`. The deadline is `started_at + RUN_BUDGET`, the same value `claim_next_job` writes to `deadline_at`.
  - `Run.has_time()`: true while `now + CLIP_AND_CHECK (2 min) <= deadline`.
  - `Run.stop(reason)`: calls `stop_job` and ignores `JobNotRunning`.
  - `Run.run_shot(shot_id, work)` runs one shot's work:
    - `out_of_credit` stops the job.
    - `JobNotRunning` drops the shot.
    - Any other exception is logged and the shot fails with `provider_error`, so the other shots carry on (RL-3).
    - Once the run is stopped, shots that have not started are skipped.
  - `finish_run(run, folder)`:
    - It does nothing when the run was already stopped.
    - With no passed shot, it stops the job with `no_shot_passed`. Each shot keeps its own failure reason.
    - Otherwise it creates `folder/cut` itself (with parent folders) and downloads the passed clips of shots that were not removed, in position order, plus the song. It assembles at 1920 × 1080 and the job's fps, stores `video-v{version+1}`, and finishes as `ready` or `ready_with_failures`.
    - Any error while cutting (bucket read or write, `MediaError`, `finish_job` refusing) stops the job with `assembly_failed` instead of crashing the worker. The clips stay in place.
    - After a finished job it calls `Comparison.record_cuts`. If that call fails, the error is logged and the job is not affected.
- `app/pipeline/clip.py`.
  - `make_clip(..., has_time=lambda: True)` asks `has_time()` before every attempt. Once the answer is no, the shot fails with `out_of_time` ("Ran out of time.").
  - An unexpected error inside the attempt loop now finishes the running attempt as `error` ("failed: The worker hit an error: <type>") before going up. A later worker restart therefore does not relabel it `worker_restarted`. The loop moved into `_attempts`, unchanged apart from recording each started attempt id.
- `app/jobs/worker_interface.py`: a new Jobs read, `cut_plan(job_id) -> CutPlan`. It returns the song key, the song offset, fps and video version, and every shot not removed, in position order, with its status, final clip key, length and transition. It is documented as `cutPlan` in ARCHITECTURE (Jobs, Interface for other modules).
- `app/pipeline/clip_stubs.py`: `get(key, path)` on the in-memory bucket. Like boto3's `download_file`, it does not create parent folders.
- Tests in `tests/pipeline/`:
  - `run_world.py`: seeds a job in the real Jobs tables. It sends clip_stubs' Jobs calls to the real interface, uses one fake clock for Jobs and the run, scripts clips and checks per shot position, and records Media.assemble and Comparison.record_cuts.
  - `test_run_stops.py` (AC2, AC3), `test_run_finish.py` (AC1, AC4-AC7, AC9, AC10) and `test_worker_start.py` (AC8).

## Key decisions and assumptions

- **Real Jobs tables instead of the Jobs stub.** The story's Stubs line predates S29, which landed the Jobs worker interface. Driving the real tables tests the real stop semantics: `stop_job` fails unfinished shots with `job_stopped`, and `finish_job` refuses an early `ready`. Files stay on the `clip_stubs` bucket so assembly reads the clips `make_clip` stored. Media and Comparison are called through their module interfaces and replaced there in tests.
- **The 2-minute margin (`CLIP_AND_CHECK`).** ARCHITECTURE Pipeline step 4 says attempts continue "while `deadline_at` leaves time for one more clip and check". VIDEO_RESEARCH §7 measured 48-88 s per clip, plus a few seconds for the check. At 29 minutes no clip is requested; at 27 minutes one is. The margin **reserves no time for assembly**, so a clip started at 28:00 plus the cut can end a little after 30 minutes. If S22's real timings show that, raise the margin or make it a setting.
- **New Jobs read `cutPlan`.** The claimed `Job` holds only pending shots, and `getJob` gives presigned URLs with no song key, offset, fps or version. Pipeline owns no tables (A-1), so the read lives in Jobs. It reads `songs.file_key` the same way Jobs already reads `provider_calls`. It is an additive interface change, now in ARCHITECTURE.
- **Runner wiring is left to S22.** S12 owns `runner.py` and was being built in parallel, and S28 handed off its own wiring the same way. Until S22 connects the pieces, the real worker has no deadline or stop handling. S22 must:
  1. Create `run = Run.for_job(job)` after `claim_next_job`.
  2. Run each pending shot as `run.run_shot(shot.id, lambda: ...)` around S12's per-shot work (prepare the photo, then the clip).
  3. Call `make_clip(..., earlier=<the round's recorded (model, error kind)>, has_time=run.has_time)` in place of S12's clip request. Without `earlier`, S28's fallback-on-resume has no effect.
  4. Call `finish_run(run, <per-job temp folder>)` once the shot pool has drained. Folder cleanup stays with S12's per-job temp folder.
  5. Swap `clip_stubs` (Jobs, Providers, Media, Files `get`/`put`) for the real calls and delete it. Comparison's `record_cuts` is already the real interface (S13 fills it in).
- PRD vs docs: the PRD sets the 30-minute target and says nothing on margins, stops or assembly order. Nothing in this story was overridden by the PRD.

- **Test tooling**: `scripts/check_ownership.main()` reads `sys.argv`, so `pytest tests/pipeline tests/gate` scans `tests/pipeline` as the app root and flags the raw SQL seeds in `run_world.py`. The gate runs `pytest` without arguments and is unaffected. The fix is for the test to call `main([])`.
