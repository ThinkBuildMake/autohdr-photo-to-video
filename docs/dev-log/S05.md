## Key decisions and assumptions

- `crop16x9` never upscales: a 16:9 crop narrower than 1920 px keeps its own size. EXIF orientation is applied before cropping.
- A transition `crossfade` starts `transitionS` early so it ends at the cut (ARCHITECTURE:409). The first shot's transition is ignored. A crossfade with `transitionS <= 0` is a cut. An unknown transition name raises `MediaError`.
- A clip shorter than its slot is held on its last frame (`tpad` clone) so cut times stay exact. A song that ends early is padded with silence (`apad`).
- Cuts are always re-encoded; no `copy` appears anywhere under `app/media` (Media's Must hold). A test inspects the ffmpeg arguments and uses inputs with keyframes every 2 s, so a stream copy would snap the cuts.
- `probe`'s fps is the stream `r_frame_rate` as a float. `assemble` returns the probed duration of its output.
- Test media is generated into `tmp_path` at test time, because `scripts/check_media.py` rejects committed jpg, png and mp4 files.

**PRD and docs:** no conflict was found between the PRD, the docs and the wireframe. The story's 1/30 s tolerance is tighter than VR-2's +/-0.1 s, which is consistent with it.

## Found late and follow-ups

All of these are minor and none affects a valid plan.

- **For S13:** on a crossfade, PySceneDetect reports the fade start (2.533 s for a fade ending at 3.0 s), not the planned cut. No S05 criterion covers it. Recording cuts against a plan is S13's job (ARCHITECTURE open question 4, line 1172).
- **ffmpeg 7.1** (the container) was not run here because there is no Docker daemon. The filters and the error string are the same in 7.1; the CI docker job is the real check.
- **Assembly runtime** on 60 s real 1080p clips (preset medium) is not measured; PF-1 timing belongs to the Pipeline stories.
- `assemble` does not validate `lengthS <= 0` or a crossfade longer than the time already assembled. A shot shorter than half a frame gets `max(1, ...)` frames, which moves every later cut by one frame. The first shot's transition name is validated although the architecture says it is ignored. Durations still reach the filter graph as Python floats in a few places.
- `tools.run` lets ffmpeg inherit stdin (no `stdin=DEVNULL` or `-nostdin`) and wraps only `FileNotFoundError`, not other `OSError`s.
- `images.py` does not wrap `DecompressionBombError` (images over about 179 MP) as `MediaError`; `thumbnail(b, 0)` raises a raw `ZeroDivisionError`. There is no test for EXIF orientation. `tests/media/synth.py:frame_rgb_mean` returns nan for an index past the last frame.
- All captured evidence uses `pytest -q`, so it shows pass counts rather than the measured values. Capturing with `-v` would put test names in the PR.
