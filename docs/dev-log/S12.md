# S12 - The worker prepares each shot's first frame and builds its prompt

**Kind:** module (M) | **Blocked by:** S01 | **Review gate:** agents
**Status:** landed by agents (no human demo). Story gate green after the review fixes: 557 passed, 5 skipped.

## Summary

Each shot starts from the photographer's photo, improved as the plan says, without ever changing a room. S12 builds the worker loop `runNextJob` and per-shot steps 1 to 3 of the pipeline. The worker claims a job and runs every pending shot at once, up to `SHOTS_IN_FLIGHT`. For each shot it crops the photo to 16:9, runs the photo-edit chain in order, and checks the edit against the crop. A changed room retries the chain once, then the shot uses the crop (`crop_only`, with a note). A failing image model moves the chain to `ENHANCE_MODEL_FALLBACK`. The worker then builds the prompt (movement prompt, speed and the lock text) and the clip length, and hands the shot to S28's `make_clip`. Temporary files go in a per-job folder on the container's disk, never on the database volume. Requirements: VR-5, OB-1. Guards: VR-5, PF-1.

## What was built

S12 calls S28's `make_clip`, which was already on the branch. Pipeline owns no table. No file from S28, S29, Providers, Media or Files was changed.

- `app/pipeline/runner.py`. `run_next_job()` claims a job through `worker_interface.claim_next_job`. It returns False when there is nothing to claim. It opens one `tempfile.TemporaryDirectory` per job in the container's temp dir, runs every shot in a `ThreadPoolExecutor(SHOTS_IN_FLIGHT)`, each in its own subfolder, and removes the folder once all shots are done. Per shot it gets the round, prepares the first frame, then calls `make_clip` with the prompt and the clip length. An exception in one shot is logged ("shot N of job J stopped", with the traceback) and never stops the others.
- `app/pipeline/prepare.py`. `first_frame(job_id, photoshoot_id, shot, round_no, folder)`:
  - Sets the shot to `editing`, crops with Media `crop16x9` and stores the crop at `jobs/{job}/shots/{position}/r{round}/cropped.jpg`.
  - With no edit prompts, records `crop_only` with no note.
  - Otherwise it runs the chain from the crop, one prompt after another, then calls `check_edit(crop, final edit)`. A changed room reruns the chain once on the same model; a second change gives `crop_only` with "The edit changed the room: <check notes>".
  - An edit error moves the chain to `ENHANCE_MODEL_FALLBACK` (skipped when it is empty or the same model). An error there gives `crop_only`.
  - A check error gives `crop_only` at once ("The edit could not be checked").
  - `out_of_credit` from the edit or the check is re-raised, so S30 can stop the job.
  - A clean edit is stored as `edited.jpg` and recorded `edited`.
- `app/pipeline/prompt.py`.
  - `LOCK_TEXT` is the VIDEO_RESEARCH §7.3 extra-lock sentence.
  - `build_prompt` gives "<movement prompt>. Camera speed: <speed>. <lock text>".
  - `clip_length` gives the shortest allowed length of `shot.model` that covers `length_s` plus the incoming crossfade. Plan position 1 has no incoming transition. If no length covers it, the longest allowed is used.
- `app/pipeline/stubs.py`. Stand-ins until S22: `get_photo` (Photoshoots plus Files.get; returns a small grey JPEG), `edit_photo(..., model)`, `check_edit`, `set_shot_photo` and `shot_round` (returns 0). The Jobs state and result writes and `put` reuse S28's `clip_stubs`.
- `tests/pipeline/shot_world.py`. Scripted world on top of S28's `clip_world`: edit errors per (shot, model), edit checks per shot, a hook inside `get_photo` for barriers, and a `put` that records the local path.
- `tests/pipeline/test_prepare_shot.py` (10 tests) and `tests/pipeline/test_run_job.py` (9 tests).

## Key decisions and assumptions

- **"First shot" is plan position 1** for the clip-length rule, not the first pending shot. A redo or restart whose first pending shot is position 3 still adds that shot's crossfade. ARCHITECTURE step 3 says "covers `length_s + transition_s`"; `transition_s` is the crossfade into the shot and is ignored on the first shot, so the build follows the shot table's definition.
- **Changed room against failing model.** Two changed-room checks give `crop_only` on that model. The fallback image model is only for edit errors (any kind except `out_of_credit`).
- **A check error gives `crop_only` at once**, with no rerun. The check is given the crop and the final edit.
- **The edit call takes the model.** The architecture has the Pipeline rerun the chain on `ENHANCE_MODEL_FALLBACK`, but `Providers.editPhoto` has no model argument. The S12 stand-in takes `model`; the real call is left to S22 (see follow-ups). No architecture text was changed, since INDEX lists no amendment for it.
- **S12 calls `make_clip` directly.** S28 was already on the branch, so the worker runs steps 1 to 5 end to end against the stand-ins. `earlier` is not passed yet.
- **Media `crop16x9` is the real function** (pure, from S05) and is patched in tests. Jobs, Providers and Files go through stand-ins, as in S28.
- **The temp folder is the system temp dir**, one per job, with a subfolder per shot, because S28's clips are named `a{n}.mp4` in the folder they are given.
- **The runner's try/except stays.** `ThreadPoolExecutor` already keeps an exception inside its future, so the except only adds the log line; without it a failed shot would be dropped silently. The test now asserts the log line.
- PRD vs docs: no conflict found. No doc other than this log was changed.
