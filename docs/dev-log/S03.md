# S03 dev log: Preset styles and Creative Commons songs can be listed, created and edited

## Summary

S03 replaces the Library stub with real reads and writes of the `songs` and `styles` tables, and adds the songs seed command with the licence rule. A style is a name, a written style text and a song; the photographer picks a preset and a style author can save one.

It builds:
- `listStyles` `GET /api/styles`, `getStyle` `GET /api/styles/{id}`, `listSongs` `GET /api/songs`, `createStyle` `POST /api/styles`, `updateStyle` `PUT /api/styles/{id}`, all on SQLAlchemy;
- the Library interface `getStyle` and `setReferenceJob`;
- `python -m app.library.seed --manifest PATH`, which adds BY-NC and BY-NC-SA tracks and refuses every other licence by name;
- the Library "Must hold" rules (GC-5 licence rule, FR-3.6 no creator video, CH-1 editing a style leaves existing jobs unchanged).

Requirements: GC-5. Supports: FR-1.2, FR-2.1, FR-2.2, FR-2.5, FR-3.6. Guards: GC-5, FR-3.6, CH-1. Kind: module. Size: M. Review gate: agents.

**Status:** landed by agents. The story gate (`bash scripts/gate.sh`) passed with 178 tests, ruff clean. No blocking review findings. No human demo is needed for this story (review gate: agents); any demo is run by the orchestrator.

## What was built

Only `app/library/` app code changed; app/jobs, app/comparison, app/photoshoots, app/web and `tests/support/fixtures.py` were not touched. No new dependency (stdlib `json`, `argparse`, `uuid`, `re`).

Subtask 1, styles and songs in the database:
- `app/library/service.py`: every function body rewritten on short `session_scope()` transactions. `list_styles` joins songs and orders by created_at, name; `list_songs` orders by title and builds the credit line `title, artist, CC <code>, source URL` in one helper; `create_style` validates text (whitespace-only counts as empty) and fps (24 or 30), checks the song (404 `song_not_found`), checks the demo photoshoot through the stub, and inserts with fps default 30 and no reference job; `update_style` touches only `styles`; `set_reference_job` records the job id (404 `job_not_found` when no jobs row). A duplicate name is caught from the UNIQUE constraint as 409 `name_taken`.
- `app/library/schemas.py`: `StyleCreate` is `extra="ignore"` so unknown fields such as `videoUrl` are dropped and never stored; `StyleUpdate` stays `extra="forbid"`.
- `app/library/stubs.py`: ids and stub data kept for other modules; `summary()` removed; added `reference_video_url` (Files.presignDownload stub, removed by S21) and `check_demo_photoshoot` (Photoshoots stub, removed by S25).
- `tests/support/library_rows.py` (`add_song`, `add_job_row`, fixture `stub_presets`), `tests/library/conftest.py`, `tests/library/test_interface.py`, rewritten `tests/contract/test_library_routes.py` and `tests/contract/test_fr_3_6_no_creator_video.py`; the `stub_presets` fixture was applied to the comparison, jobs drafts, pages and e2e styles tests with no assertion changes.

Subtask 2, seed command:
- `app/library/seed.py`: `ALLOWED = ('BY-NC', 'BY-NC-SA')`, `normalise_licence`, `SeedResult`, `seed_songs`, `main`. Songs are upserted with id `uuid5(NAMESPACE_URL, sourceUrl)`, so a second run updates instead of duplicating. It prints `added: ...` to stdout and `refused: ... : <reason>` to stderr, and exits 1 when any track was refused (allowed tracks are still added).
- `tests/library/test_seed.py`: synthetic manifests in `tmp_path`.
- The real external manifest at `/home/user/assets/songs/manifest.json` was run against a throwaway database (3 tracks added as BY-NC); no audio or manifest was copied into the repo.

## Key decisions and assumptions

The standing rule was no questions, so these were assumed and noted in the plan:
- The credit line is `title, artist, CC <code>, source URL` with no licence version, because no column holds one.
- Whitespace-only style text counts as empty (400 `invalid_style`).
- The manifest is JSON with `title`, `artist`, `licence`, `sourceUrl`, `fileKey`, `durationS`. The seed also accepts a bare list and snake_case aliases (`source_url`, `duration_s`, `file_key`, `file`) so the external real manifest loads unchanged; the licence rule applies to every format.
- Song id is `uuid5` of the source URL, so re-seeding updates.
- The seed exits 1 when any track is refused but still adds the allowed ones.
- `setReferenceJob` with a job id that has no jobs row answers 404 `job_not_found`.
- Demo photoshoot check and reference video link stay stubbed in `app/library/stubs.py` (S25 and S21 remove them).
- Tests that relied on stub rows now seed them through the shared `stub_presets` fixture, because Library reads the database.

### Where the docs or story were adjusted (PRD check)

- Criterion 11 says a POST with an extra `videoUrl` creates the style, while the S01 FR-3.6 guard test expected 400 `invalid_request`. The guard was changed to "201, field dropped, never stored, and no video column in `styles`"; the upload tests and the no-video-column test stay. `StyleUpdate` still refuses extra fields with 400.
- The PRD (`docs/AutoHDR Photo to Video.pdf`) lists a past video and a storyboard outline only as non-binding examples ("not meant to bias you") and wants a style reproduced "down to the song". The docs' choice of text plus song with no outside video (FR-3.6) does not contradict it. The PRD says nothing about licences, so GC-5 comes from the docs and USERS. No place where the PRD overrode the docs or wireframe was found in this story.
