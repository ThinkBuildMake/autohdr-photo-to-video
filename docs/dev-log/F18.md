# F18 — Standalone carried leftovers

## Changes

1. `app/providers/calls.py` owns the chat and clip call write paths. Video generation,
   fake video and recovery use it. `clip_calls.py` is removed. Recovery metadata,
   scrubbed errors and the rule against lowering recorded clip cost are preserved.
2. Draft and finished-shot edits survive a provider model-list failure. The edit is
   saved with a persistent warning in `planNotes` or `planNote`. Finished-shot saves return 200 with the saved shot, export plan and a warning
   field. The editor reconciles the saved state and displays the warning separately
   from validation errors. Draft saves return 200. Local validation
   still applies. Planning keeps its existing strict model validation.
3. Completing an upload claims the labelling status atomically. A repeat while
   labelling runs does not start another background job. Startup recovery and
   retrying a failed label run retain their existing paths.

## Decisions

- The supplied story has three explicit fixes and no criterion map. Each fix is
  treated as its own test criterion, with route tests for both edit entry points.
- During a model-list outage, save the edit and warn that model limits were not
  checked. Do not invent model durations. This is the story's graceful-degradation
  option; provider generation will still enforce its limits.
- The PRD's editable project requirement and REQUIREMENTS RL-1 agree with these
  changes. No PRD conflict was found. These implementation decisions stay in this
  dev log; the architecture contract is unchanged. Completion avoids starting
  another labelling run while one is active.
