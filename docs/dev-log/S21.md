# S21 - Choose a style, edit its text and get a shot plan for a real photoshoot

**Kind:** wiring | **Blocked by:** S03, S07, S09, S20 | **Review gate:** human demo
**Status:** landed by agents. Spec review passed (round 2). Logic review passed with one minor. Gate after simplify: 764 passed, 5 skipped. The human demo on the deployed app is still outstanding.

## Summary

The New video plan and the Styles page now use the real library, photos and planner. A song preview is a presigned link to the song file. Creating a job downloads thumbnail copies of the uploaded photos and asks Providers for the plan. An invalid plan is refused once and asked again. Two bad answers, or a planner `bad_response` twice, mark the plan failed and the page offers Try again. The gate mocks OpenRouter. The real Free Music Archive tracks are still a demo setup step.

## Decisions

- `photoshoots.planner_photos` returns `{photoId, room, subject, jpegBytes}` for uploaded photos, in upload order. The bytes are a thumbnail at `LABEL_IMAGE_LONG_SIDE`. `listPhotos` stays a list of `Photo`.
- Jobs calls `providers.plan_shots` and `providers.allowed_lengths`. FakeProviders still answers when `FAKE_PROVIDERS=1`.
- A shot length that is not on the video model's menu is refused in planning. The editor can still store a shorter cut, so that check is not in `validate_plan`.
- The plan-step browser tests no longer intercept Jobs or Photoshoots. They upload into the fake bucket and mock the planner transport.

## Follow-up

Saving or editing shots calls the live video-model list. If that list times out, `allowed_lengths` raises and the save returns 500, so the edit is not stored. Planning already records a provider failure on the job. The save and edit paths do not.
