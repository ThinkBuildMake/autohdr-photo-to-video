## Key decisions and assumptions

- **One attempt, no retries.** Every chat call makes one HTTP request with a finite timeout; none retries after 402, 429, a refusal or a timeout (RL-1). The one exception by design is `edit_photo`'s single fallback to `ENHANCE_MODEL_FALLBACK`, after `failed` or `bad_response` only, with its own row.
- **Error mapping.** 429 is `rate_limited` (`retry_after_s` read from `Retry-After` when numeric), 402 `out_of_credit`, 403 / moderation reasons / `finish_reason` `content_filter` / native refusal reasons `refused`, 408 and httpx timeouts `timeout`, other HTTP and transport errors (a 401 too) `failed`, an `error` object inside a 200 body is mapped by its code, non-JSON or off-shape answers `bad_response`.
- **Cost rule.** BYOK when `usage.is_byok` is true or the model is in the comma-separated `BYOK_MODELS`: cost is tokens times list price from `/models`, `cost_source` `list_price` (`image_output` price when the answer carried images). Otherwise the reported `usage.cost`. If the price list cannot be read, cost is 0 with `list_price` and a warning, and the failure is not cached. Nothing reads `provider_calls` totals before sending (GC-3).
- **Key safety.** The key is only in the `Authorization` header; every error text goes through `scrub()` and is cut to 500 characters; logs carry kind, model, status and error kind only; errors are raised `from None`.
- **Every call leaves exactly one closed row.** The row is closed before the `ProviderError` is raised; a bad response after a successful 200 re-closes the row as an error but keeps the cost (the money was spent). A catch-all in `chat()` turns unexpected exceptions into `bad_response`.
- **The app decides (VR-5).** `architectureChanged` is the model's flag OR any listed object containing an architecture word; `passed` comes from the thresholds, the person count and the three lists, never from the model's own `passed`. Every edit prompt ends with "preserve all architectural and interior details".
- **Assumptions recorded in the plan.** `labelPhotos` is one request for all photos; callers make the small photo copies; `checkClip` sends the clip inline as a `video_url` data URL when the file exists, plus the frames (ARCHITECTURE open question 2, option A); plan lengths against the song and the "invalid plan retried once" rule stay with Jobs (S09).
- **Plain synchronous code.** `httpx.Client`, no async; state shared across parallel shots (price cache, fake counters) is lock-guarded. `interface.py` makes a new provider object per call, so the fake's state is module-level.
- **Tests never reach the network.** Real-client tests install `httpx.MockTransport`; each call has one `@pytest.mark.live` test that runs only with `OPENROUTER_LIVE=1` and a real key; synthetic images are drawn at runtime and never committed.

PRD versus docs: the PRD (`docs/AutoHDR Photo to Video.pdf`) did not need to override the docs or the wireframe anywhere in this story. Three docs notes:
- REQUIREMENTS CO-1 says BYOK cost is "seconds x list price", which is video wording. Chat calls record tokens x list price. Kept as a recorded assumption; AC9 only needs `list_price` and a cost above 0. Mention it in the PR description.
- ARCHITECTURE open question 7 was marked [verify]: OpenRouter's usage object does carry `is_byok` and `cost`. No contract change.
- ARCHITECTURE puts a fallback "on fail or refuse" at the Pipeline level (S12). `editPhoto` already falls back once after `failed` or `bad_response`, so S12 must not call the fallback model a second time for the same failure.
