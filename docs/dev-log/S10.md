# S10 dev log: A submitted job waits its turn, and the photographer can list jobs and open their videos

## Summary

The Jobs queue module now reads and writes the database. `POST /api/jobs/{id}/submit` moves a ready draft to `queued` (it never starts a second running job, so a second job waits behind the running one). `GET /api/jobs` lists jobs newest first with status and elapsed time. `GET /api/jobs/{id}` returns the job with its shots, showing only the final passed clip of each shot, and `waitingBehind` for a queued job. `GET /api/jobs/{id}/video` returns a play link, a download link and the duration, or 409 `no_video`. The measurement record `first_submitted_at` (set once) and `submitted_at` (set on every submit) is written at submit.

## What was built

Files (all in the Jobs module plus tests):

- `app/jobs/reading.py` (new, 169 lines): `now_utc`, `elapsed_s`, `running_job_id`, `load_job`, `list_jobs`.
  - `load_job` turns the jobs, job_shots and attempts rows into the shared `Job` type. A shot's `clip_url` comes only from its final attempt, and only when that attempt's status is `passed`. The attempt count covers the shot's current round only. `waiting_behind` is the running job's id when the job is queued. The video link is presigned only when `video_key` is set.
  - `list_jobs` left-joins photoshoots (read only, for the label), orders by `created_at` desc then `id` desc, and takes style names from one library lookup ("Custom style" when none).
  - Presigning happens after the session closes.
- `app/jobs/queue.py` (rewritten):
  - `get_job` keeps the stub answer for `STUB_JOB_ID` (sibling stubs and pages still use it) and otherwise calls `reading.load_job`.
  - `list_jobs` calls `reading.list_jobs`.
  - `submit_job` runs in one transaction and checks in this order: 404 `job_not_found`, 409 `not_draft`, 409 `plan_not_ready`, 409 `no_shots_to_make`. It then runs a conditional `UPDATE ... WHERE status='draft'` that sets `submitted_at` and `first_submitted_at = coalesce(first_submitted_at, now)`, and marks photo-less shots `skipped` with `no_photo`. It never touches another job.
  - `get_video` returns `{url, download_url, duration_s}`, or 409 `no_video` when `video_key` is null.
- Tests: `tests/jobs_queue/{conftest,test_reading,test_queue_routes}.py` (new), `tests/support/queue_rows.py` (new, raw-SQL synthetic seed helpers), `tests/contract/test_jobs_queue_routes.py` (reseeded with real rows), `tests/access/test_passphrase.py` (gate test now submits three real ready drafts, then one without auth gets 401 and stays a draft).
- Routes, schemas and shared types are unchanged: they already matched the contract. No new dependency. Diff against the base: 8 files, +794/-25.

## Key decisions and assumptions

- Files.presignDownload: the story lists a stub (removed by S22), but S04 already landed the real `app.files.service.presign_download`. S10 calls it directly and writes no stub, so S22 has nothing to remove here.
- "Nothing to make" means no shot with a photo that is not removed. Submit marks photo-less shots `skipped` / `no_photo` so getJob shows them while queued (RL-2). The architecture does not pin who marks them; S29/S12 should treat `skipped` shots as done.
- `waitingBehind` is the running job's id only, and null when nothing is running, even behind other queued jobs.
- `elapsedS` is now minus submittedAt for queued and running jobs, finishedAt minus submittedAt after, and 0 for drafts.
- `no_video` means `video_key` is null. A re-run keeps its previous version playable.
- The download file name is `video-{first 8 of id}-v{video_version}.mp4`.
- `plan_not_ready` (409) is an added error code; the architecture allows more codes.
- `JobShot.model` shows `model_used` when set. S09's store uses the row's `model`; the two conventions differ only once a fallback model was used.
- `queue.get_job` keeps answering the stub for `STUB_JOB_ID` so the drafts/edits/comparison stubs, the job and editor pages and their tests stay green. `submit_job`, `list_jobs` and `get_video` never use the stub.

PRD overrides: none. No conflict between the docs and the PRD was found in any stage.

Merge note for S09 (built in parallel): both stories change `app/jobs/queue.py`. S10's version is taken, and the `store` import is dropped from it if unused. `reading.load_job` follows `store.load_job`'s field conventions so S09's getJob tests keep passing.
