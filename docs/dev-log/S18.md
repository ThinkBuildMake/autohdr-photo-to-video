# S18 - Create a style, try it on a demo shoot, and lay a reproduction beside the reference video

**Kind:** module (M) | **Blocked by:** S01 | **Review gate:** agents
**Status:** built by agents and reviewed twice (spec passed both rounds; logic round 1 had 3 blocking findings, logic round 2 had 1 blocking and 1 minor). Round 1 and round 2 fixes are applied. Story gate after the round 2 fixes: 721 passed, 5 skipped.

## Summary

A style author writes a style and tries it until it looks right. Anyone can then check that the style holds on a different house.

- **Create a style** (`/styles/new`). The form takes a style name, the author's name, a song (its licence and credit appear beside the picker), the frame rate, the style text and a demo photoshoot. There is no video upload anywhere (FR-3.6). "Try it on the demo shoot" saves the style (createStyle the first time, updateStyle after that) and starts a try (createJob, purpose `video`). The page polls the try, submits it once its plan is ready, and shows the plan table, the video and the song credit. "Use as reference video" sends the try to setReference.
- **Reference and reproduction** (`/styles/{id}/reproductions`). A tab per reproduction of the style. Two players with "Play both together". "Same song / Same style text / Shots flagged". A summary table of both plans (shots, length, typical shot, movements, transitions). Shot rows lined up by position, with cut errors against each video's own plan and flagged shots marked, and the worst cut error. The no-reference message appears when getReproduction answers 409 `no_reference`.

Both pages call the real `/api/...` routes. The browser tests answer those routes with Playwright `page.route` stand-ins and record what the page sends. The screens follow the wireframe's layout, wording and colours.

## What was built

- `app/web/templates/create_style.html`, `app/web/pages/create_style.py`, `app/web/static/create_style.js`: the Create a style page. The server renders the songs (with licence, credit and source URL as data attributes) and the demo shoots. The script saves the style, starts and follows the try, renders the plan and the video, and sets the reference.
- `app/web/templates/compare.html`, `app/web/static/compare.js`: the Reference and reproduction page. The server renders the style's id and name; the script reads listJobs, picks a reproduction and renders getReproduction. `app/web/pages/compare.py` is unchanged.

- `docs/ARCHITECTURE.md`, `docs/stories/INDEX.md`: the listPhotoshoots route (below).

## Key decisions and assumptions

- **listPhotoshoots, reconciled with S15.** S18 needed a list of shoots for the demo-shoot picker and first built its own read (with status and photo count) plus a route. S15 landed first with a read-only `list_photoshoots() -> [(id, label)]` (every shoot past `awaiting_upload`, newest first) and INDEX "Architectural issues" item 9. On the rebase, S18's duplicate function was dropped. The route now serves S15's function as JSON, and the demo-shoot picker shows only the label. ARCHITECTURE has one listPhotoshoots entry in the API that points at the interface entry, and the interface entry names the route. INDEX item 9 now says S18 added the route.
- **A style's reproductions come from listJobs, filtered by purpose `reproduction` and the style's name.** Style names are unique and listJobs reads them from the styles table. Filtering by style id would need `styleId` on `JobListItem`, which is a shared type in the Jobs contract, so that is left as a follow-up. The page picks `?jobId=` when given. Otherwise it picks the newest finished reproduction (ready or ready_with_failures), or the newest of all if none has finished.
- **A try** is createJob with purpose `video`, the style's id, text and song, and the demo shoot. The page submits it as soon as the plan is ready and polls getJob every 5 s (ARCHITECTURE data flows). A new try stops following the previous one only after the style save succeeds. A submit response for a try the page has left is ignored.
- **"Use as reference video"** is enabled only for a try whose status is `ready`, because setReference refuses anything else (S13). It is turned off after a revision's style save succeeds, so a failed save leaves the ready try on screen, the button on, and that try still followed.
- **Wording.** "Use as reference video" uses the story's words (the wireframe says "Use as the reference video"). "Try it on the demo shoot" and "Play both together" follow the wireframe.
- **Shot rows.** getReproduction gives one `movementName` per row, so the table has one Movement column, then both lengths, both cut errors ("ref / repro", marked "over" when the absolute error is above 0.1 s) and the flag.
- **Links.** Video URLs go only into `src`, and song source URLs only into a "source" link's `href`, never as text. A song credit shows as "title, artist, CC licence · source".
- **Errors.** Both scripts check the response status and content type before parsing JSON. An error page that is not JSON shows "The server answered 502 Bad Gateway." The page's own wording is used for `no_reference`.
- PRD vs docs: no place was found where the PRD overrode the docs or the wireframe.

## Found late / follow-ups

- **Filter reproductions by style id.** Add `styleId` to `JobListItem` (the Jobs listJobs contract and a shared type) and filter on it instead of the style's name. This touches the Jobs module's contract, so it was left out of this story.
- **"Play both together" does not keep the videos in sync.** Pause and seek both together on `waiting` and `pause`, and show a rejected `play()`.
- S25: the screens call the real routes unchanged. The author name and the demo shoot are fixed after the first try, because updateStyle accepts neither.
- The wireframe's "Save style", "Run on another shoot", "Keep style in the library" and "Edit the style text" controls are not in this story. The style is saved on the first "Try it", and reproductions start from the Styles card (S15).
- When a style has no reproductions, the page says "No reproductions of this style yet." without checking whether it has a reference.
- The `.screen` rules in `style_pages.css` repeat parts of S15's `app.css`. They can be folded into `app.css` once the shared layout settles.
