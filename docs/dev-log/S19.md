## What was built

- `docs/SCALING.md`. The scaling explanation. Today: one container, one worker, one SQLite file, one running job. For N jobs: several workers claiming with a conditional update, Postgres as a connection-string change, recovery limited to the worker's own jobs, a shared cap on clips in flight, and cost growing linearly. Each job keeps PF-1 (`first_finished_at − first_submitted_at`); a job left queued can miss it. The claim-time budget is PF-3 (`deadline_at` = `started_at` + 30 min). Then one section for each next piece, quoting its trigger. Queue wait for a job that has not started is now − `submitted_at`.
- `README.md`. Setup with `FAKE_PROVIDERS=1` on the `honcho start` line, the passphrase, `/healthz`, real-provider and bucket variables, tests and the gate, deploy, a design table of the ten modules and the four outside services, a short scaling section linking `docs/SCALING.md`, a results placeholder, and a document index.
- `tests/docs/test_scaling.py`. The scaling checks: the N-jobs limit and outputs, the unstarted queue wait, and one section per next piece.
- `tests/docs/test_readme.py`. Copies a fresh-clone file set into a temp directory, runs the README's setup block, starts the `honcho start` line on a free port, and checks `/healthz` and `/`.
- `tests/support/markdown.py`. Shared heading splitter, moved out of the scaling test when the README test needed it.

## Key decisions and assumptions

- **The scaling explanation lives in `docs/SCALING.md`, linked from the README.** No document named a place for it, and the story says two documents. No other doc changed.
- **The fake setup sets variables on the command line, not in `.env`.** Honcho reads `.env` and those values override the shell, so the README says so and tells anyone who has a `.env` to put the values there.
- **`PORT=8000` is explicit.** Honcho's default base port is 5000, which the macOS AirPlay receiver holds. The README also says what to do when 8000 is already taken (this machine had an unrelated process on it; the manual check used 8001).
- **No model identifiers** in the README or the scaling document. They name OpenRouter, Railway and SQLite, and describe models by kind ("a fallback video model").
- **Scaling content** follows the high-level design's "what to add next" and sizing notes, the architecture's claim rule, deadline, recovery and provider-call records, and the stack note that moving to Postgres is a connection-string change.
- **The results section is a marked placeholder for S26**, with no numbers.
- PRD vs docs: no disagreement found for this story.
