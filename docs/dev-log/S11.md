# S11 - A finished or stopped job can be started again, have one shot redone, or be edited and re-exported

**Kind:** module (M) | **Blocked by:** S09, S29 | **Review gate:** agents
**Status:** landed by agents (no human demo). Story gate green after the round 1 fixes: 568 passed, 5 skipped.

## Summary

The photographer can fix a video without paying again for shots that were already fine. S11 replaces the S01 stubs behind four routes. `POST /api/jobs/{id}/restart` starts a stopped job again. `POST /api/jobs/{id}/shots/{position}/redo` redoes one shot of a finished video. `PATCH /api/jobs/{id}/shots/{position}` edits one shot in the editor. `POST /api/jobs/{id}/export` re-exports the edited video. Restart, redo and export only set shots back to `pending` in a new round and queue the job. The worker then makes the pending shots and re-cuts the video. An edit only records what the next export will do with the shot: make a new clip, only re-cut, or nothing. Requirements: CH-1. Guards: CH-1, QC-2.

## What was built

- `app/jobs/edits.py`. The four stubs were replaced with database writes. Each call is one transaction whose first statement is a no-op write on the job (the S29 pattern), so it is serialised with the worker's `claim_next_job`.
  - `restart_job`: only a `stopped` job, otherwise 409 `not_stopped`. Every shot that is not `passed` or `skipped`, has a photo and is not removed goes back to `pending`.
  - `redo_shot`: only a `ready` or `ready_with_failures` job. It answers 409 `job_busy` while queued or running, and 409 `not_finished` for a draft or stopped job. It also answers 404 `shot_not_found`, 409 `no_photo`, and 409 `shot_removed` (new).
  - `edit_shot`: same job checks as redo. The edited shot is validated alone with `plan_rules.validate_plan`: photo in this photoshoot, known movement, speed and transition, length within the model's longest clip. A bad edit answers 400 `invalid_edit`, and the message is renumbered to the shot's position. It returns the shot and the export plan `{newClips, recutOnly, removed}`.
  - `export_job`: same job checks. It answers 409 `nothing_to_export` when no shot changed since the current run was queued. Only shots needing a new clip that have a photo and are not removed go back to `pending`.
  - All three requeue paths add 1 to the round, clear `final_attempt_id`, the failure reason, the detail and `needs_new_clip`. They then queue the job with a new `submitted_at` and clear `stop_reason`. `first_submitted_at` is kept.
- `app/jobs/reading.py`. `edited_since(row, submitted_at)` and `pending_change(row, submitted_at)`. `getJob` now reports `recut_only`.
- Tests:
  - `tests/jobs_edits/` (new): a `make_job` factory in the conftest, plus `test_restart_redo.py`, `test_edit_shot.py` and `test_export.py` (30 tests after the fixes).
  - `tests/contract/test_jobs_edits_routes.py`: rewritten on a seeded job.
  - `tests/support/queue_rows.py`: `add_attempt(requested_s=...)` and `shot_rows(job_id)`.
- Docs:
  - ARCHITECTURE: the editShot and restartJob rows, the CH-1 Must hold, the redoShot errors, and the `submitted_at` and `round` columns.
  - REQUIREMENTS FR-1.16.
  - INDEX: amendments 2 and 8 marked resolved.

## Key decisions and assumptions

- **INDEX amendment 8:** a speed change needs a new clip (AC15). ARCHITECTURE editShot and FR-1.16 now list speed.
- **INDEX amendment 2:** CH-1 now reads "copied shot fields change only through updateJobShots before submit and editShot after; restart, redo and export never change them".
- **A length edit longer than the existing clip** needs a new clip. The rule is length + transition above the final attempt's `requested_s`. A shot with no passed clip counts as 0 s, unless it has no photo (see fix 1). Shorter length and transition edits are re-cut only (AC7). ARCHITECTURE editShot and FR-1.16 both say this.
- **Redoing a removed shot** answers 409 `shot_removed`: put the shot back first.
- **Restart leaves skipped (no photo) and removed shots as they are.**
- **pendingChange:**
  - A removed shot shows `none`.
  - Otherwise `new_clip` when `needs_new_clip` is set.
  - Otherwise `recut_only` when the shot was edited after the job's current run was queued (`edited_at > submitted_at`).
  - Otherwise `none`.
  - Export counts a removal made after the last run as a change, even though the removed shot shows `none`.
- **An edit is recorded only when a value changes.** A same-value PATCH sets no `edited_at`.
- **Putting a shot back before an export** keeps its fields, clip and `needs_new_clip`, but counts as a re-cut. There is no edit history to tell it apart from a put-back after an export.
- Changing the movement without a prompt resets the prompt to the starter-kit text. Swapping the photo takes the photo's room label when it has one. Field edits set `plan_note` to `changed_by_photographer`.
- The editor does not check the song length: ARCHITECTURE's `invalid_edit` list has no such rule.
- PRD vs docs: no conflict. PRD p.7 asks for swap a room, change a shot, remove a room, re-export.

## Found late / follow-ups

- **S23/S24: redo moves the run clock.** Redo requeues only the named shot and sets `submitted_at` to now. Shots with `needs_new_clip` keep their flag but are not made in that run. Re-cut-only edits stop showing in `pendingChange` because their `edited_at` is now earlier than `submitted_at`. One option is to refuse a redo while any shot has a pending change ("export first"). The other is for redo to also requeue the `needs_new_clip` shots.
- **S30 (assembly):**
  - A re-export with only re-cut changes queues a job with no pending shot. The worker must still re-cut it and finish it with a new `video_version`.
  - Assembly must leave out removed shots.
