# S14 - One command runs the 12 test shoots and writes the reports a reviewer fills in

**Kind:** module (M) | **Blocked by:** S01 | **Review gate:** agents
**Status:** landed by agents (no human demo). Story gate green on the final run: 553 passed, 5 skipped.

## Summary

VR-1 and VR-3 to VR-6 need a person to judge each shot. S14 builds the Evals command line that runs the jobs, lays out what to judge, and turns the filled sheet into numbers:
- `evals import` loads one photoshoot per test-shoot folder and reuses a shoot already uploaded under the same label.
- `evals run --suite ev1|ev2 --style NAME` creates and submits the jobs, waits for them to finish, and writes a reviewer sheet and a first report.
- `evals report --sheet S` writes a new report from the filled sheet and the job tables.

Photoshoots.importPhotoshoot, Jobs.createJob and Jobs.submitJob are called through stubs, which S26 removes. Everything was built and tested on synthetic shoots and seeded jobs. No real test shoot is read (GC-9). Requirements: EV-1, EV-2, GC-6, GC-9. Guard: GC-9.

## What was built

- `app/evals/stubs.py`: stand-ins for `import_photoshoot(paths, label)`, `create_job(body: JobCreate)` and `submit_job(job_id)`. They return new ids and touch no table. Evals calls them as `stubs.fn(...)` so tests patch them and S26 swaps in the real calls.
- `app/evals/shoots.py`, `evals import --folder F [--out O]`:
  - Each subfolder becomes a photoshoot named after the folder. A label already in `photoshoots` is reused.
  - Only `.jpg`, `.jpeg` and `.png` files go to the import, in any case.
  - Writes `O/shoots.json` (label to photoshoot id). The default `O` is `evals/reports`.
- `app/evals/runs.py`, `evals run --suite ev1|ev2 --style NAME [--out O]`:
  - Looks up the style by name. EV-1 makes one `video` job per shoot. EV-2 makes `reproduction` jobs on the first 2 shoots that are not the style's demo shoot. Every job gets the style's text unchanged, its song and its id.
  - Each job is created and submitted through the stubs. The run then polls job statuses every 30 s until all are ready, ready_with_failures or stopped.
  - Writes `O/<suite>-<stamp>/sheet.csv` and a first report. Without `shoots.json` it exits with "run `evals import` first".
- `app/evals/report.py`, `evals report --sheet S`, writes `report-<stamp>.md` beside the sheet. The report has:
  - a per-video table: shoot, style, job, status or stop reason, visibly AI shots, rooms changed, movement and transition matches, worst cut error and job time;
  - the median job time;
  - the stopped jobs with their reasons;
  - a per-style table: reproductions like the reference, plans text followed and worst cut error;
  - the QC-1 catch rate.

  It reads BOM-prefixed (Excel "CSV UTF-8") sheets, and a yes cell is yes, y or x in any case.
- Evals only reads tables (`select`). The table-ownership gate stays green.
- `docs/ARCHITECTURE.md` Evals contract: INDEX amendment 4 applied (see decisions). `docs/stories/INDEX.md` issue 4 notes it.
- Tests: `tests/evals/test_import.py` (2), `tests/evals/test_run.py` (5), `tests/evals/test_report.py` (8), `tests/evals/conftest.py` (the `world` and `fake_jobs` fixtures) and `tests/support/evals_rows.py` (raw-SQL synthetic seeds). 15 tests in all. No new dependency.

## Key decisions and assumptions

- **One CSV sheet with a `kind` column** (`attempt`, `plan` or `reproduction`). An EV-2 sheet has to hold all three kinds, so criterion 4's "30 rows" counts the `attempt` rows and criterion 5's rows are the `plan` and `reproduction` rows. The spec review accepted this as the only reading where criteria 4 and 5 both hold.
- **INDEX amendment 4 applied.** The ARCHITECTURE Evals contract now lists a `text_followed` row per plan (VR-3) and a `looks_like_reference` row per reproduction (VR-4). COMMON allows the amendments listed under INDEX "Architectural issues"; the spec review accepted the change.
- **"not found" for stub jobs.** A job id with no row counts as finished and is reported "not found". The default stubs write no row, so without this `evals run` would poll forever. These jobs add no job time, so they don't skew the median. Once S26 swaps in the real createJob, every id has a row.
- **Import state goes in `shoots.json`.** Evals owns no table, and the stubbed import writes no row, so `run` reads the file `import` wrote.
- **"Video N"** is the Nth job the run created; the sheet has a `video` column.
- **Visibly AI and room changed count per video** only when the reviewer marked the delivered attempt: the shot passed, it isn't removed, and the attempt is the shot's final one (`in_video` = yes). A reviewer "failed" an attempt by marking it visibly AI or room changed. The check "flagged" it when the attempt status is `flagged`.
- **Job time** is `first_finished_at − first_submitted_at`, as in the ARCHITECTURE Measurement table for PF-1.
- **Report files** use a microsecond stamp, so a second report never overwrites the first ("reports are new files").
- **PRD vs docs:** the PRD only names the 12 test shoots as the test set. Nothing in the docs conflicted with it.

## Found late / follow-ups

- **S26 swaps the stubs** for `photoshoots.service.import_photoshoot`, `jobs.drafts.create_job` (it returns a `Job`; use `.id`) and `jobs.queue.submit_job`. A real createJob returns a draft that is still planning, so the run must wait for `plan_status = ready` before it submits. Once that's in, treat a missing job row as an error and give `_wait` a deadline.
- **Sheet links expire.** Clip and video links are 1-hour presigned links, and a review takes about 2 hours. Either rewrite the sheet links just before review or give Evals a longer link expiry.
- **Sheet columns for S26:** a round column (or `round.attempt`), a reference-video link on reproduction rows, and the style text or a job-page link on plan rows.
- **Duplicate labels:** pick the newest photoshoot per label.
- **Run-folder stamp:** use the report's microsecond stamp so back-to-back stubbed runs cannot collide.
- `evals run --suite ev2` takes one style per call; S26 calls it once per preset.
