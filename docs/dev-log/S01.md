### Key decisions and assumptions

- **Bucket host.** `.env.example` said `https://storage.railway.app`. The Railway docs give `t3.storageapi.dev`, so `BUCKET_ENDPOINT` now defaults to that, and the approved-host check allows `openrouter.ai` plus `t3.storageapi.dev` and its subdomains. The architecture only says "Railway Storage Bucket", so it does not change.
- **`started_at` NOT NULL.** ARCHITECTURE leaves the Null cell blank for `attempts.started_at` and `provider_calls.started_at`. They are NOT NULL with no default (`finished_at` is nullable), so S06 and S28 must supply `started_at` on insert.
- **Procfile uses `exec`.** honcho runs each line through `sh -c`, and dash does not exec. SIGTERM to the pid honcho reports then hit the shell and orphaned the Python child, so honcho never exited. With `exec` the reported pid is the real process and AC7 holds. The web line is first so it gets `$PORT`.
- **CI push trigger includes `main`.** The plan listed only `claude/dazzling-keller-xgo5vz`. `main` was added at the orchestrator's request. There is still no `cancel-in-progress` (Railway "Wait for CI" ignores cancelled runs).
- **Pinned versions.** `playwright==1.56.0` (matches the preinstalled Chromium 1194), `sqlalchemy>=2.0.55,<2.1`, `scenedetect==0.6.7.1` with `opencv-python-headless<5`, `honcho==2.0.0`, uv 0.11.32 in the Dockerfile and CI. Later stories' libraries were added now so parallel stories never edit `pyproject.toml` at the same time.
- **No Docker daemon here.** Criterion 13 is checked locally by Dockerfile and lockfile tests plus starting the container's own command with `FAKE_PROVIDERS=1`. The real build and run is the CI `docker` job.
- **Stub details.** Stub song `source_url` is `stub://songs/sunrise-walk` (the GC-4 check forbids other http URLs in `app/`). The `getReproduction` summary `movements` and `transitions` are name-to-count objects (ARCHITECTURE leaves the shape open). State-dependent 409s are not simulated; they belong to S09 to S11.
- **Handlers.** Every route and page handler is a plain `def` (Blocking work contract, enforced by `tests/app/test_blocking.py`). Newer FastAPI wraps included routers, so the test walks `original_router.routes`.
- **Seams.** Routes call module functions through the module attribute (`service.list_styles()`) so later stories can monkeypatch the stubs. One file per owner story; README.md is untouched (S19).

## Found late / follow-ups

- **init_db race.** Web and worker both run `create_all` on a fresh file at the same moment. Not seen on the real start path, but a first Railway boot could fail once and heal on restart. Fix: take an exclusive lock around `create_all`, retry once on "already exists", or let only the web process create tables. Check the first Railway boot log for "table ... already exists".
- **Catch-all error handler.** Add a 500 handler returning `{error: "internal_error", message}` without echoing the exception text, before later stories raise real errors (owner: S02 or the first story that needs it).
- **Host check coverage.** Extend `scripts/check_hosts.py` to templates and static CSS so a screen story cannot add a CDN link unnoticed (GC-4).
- **Test teardown.** Start honcho in its own process group in `tests/deploy/test_processes.py`, kill the group on teardown, and assert the worker pid is gone in the `web.1` case.
- **CI.** Add `--max-time` to the docker smoke `curl` and `timeout-minutes` to the job; tighten `test_ci_workflow.py` against `|| true` and job-level `cancel-in-progress`.
- **Ownership check.** Handle `UPDATE OR <x>`, `Model.__table__`, query-chain updates and import aliases; per-function name tracking. The static check cannot see ORM attribute mutation (`job.status = 'x'`) or dynamically built SQL, so reviewers of S03 to S30 must still watch for those.
- **Later stories.** `attempts.started_at` and `provider_calls.started_at` are NOT NULL (S06, S28). S08 should add `too_large` to `Photo.status`. The stub deviations listed in the bug log belong to S03, S09, S11 and S13.
- **Dependency ages.** Release ages of htmx 2.0.11, ruff 0.17.1 and astral-sh/setup-uv v7 were not checked against a two-week minimum.
- **Credentials.** Pushing `.github/workflows/ci.yml` needs a token with the `workflow` scope.
