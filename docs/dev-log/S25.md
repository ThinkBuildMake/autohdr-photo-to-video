## What was built

1. **Style authoring and Library playback.** Create a style saves and edits through the real Library, picks the demo shoot from Photoshoots, and runs "Try it" as a real job. Each try keeps a snapshot of the text and song it used. "Use as reference video" sets the reference, and the Styles card shows it. Playback links are real signed links for files under `photoshoots/`, `jobs/` or `songs/`. The Library stubs shrank to constants. Changing the style text clears the reference, because the reference no longer matches the style. Save and poll errors are shown separately, so a failed poll no longer reads as a failed save.
2. **Comparison with real signing.** A reproduction is compared with its reference through real signed links. `comparison/stubs.py` is deleted. A shot that was omitted from a video gets no timing, so it never shows an invented length or cut.
3. **Reproduction and compare page.** The Styles page reproduction form reads the style's saved text and song when it submits, and ignores a second submit while one is in flight. The compare page follows the wireframe: Shot by shot has Reference, Reproduction, Cuts vs each plan and Flag columns, each side with its own length, movement and transition. Each video's worst cut error comes from its own rows. A cut more than 0.1 s early or late is marked over. Buttons: Run on another shoot, Keep style in the library, Edit the style text. "Play both together" starts both from 0, links pause, seek and buffering, and corrects drift above 0.1 s. A rejected play shows "Playback could not start".
4. **Story-review fix.** The reference also goes stale when the song or frame rate changes. `set_reference` refuses a job whose song or frame rate does not match the style. `same_song` is judged against the reference job's song. `get_reproduction` only accepts a reproduction job of this style. The compare page says how many cuts were not measured. Play both no longer stops the longer video when the shorter one ends.

## Decisions

- **Reference follows the style's text, song and frame rate.** Any change to those makes the reference a video of a different style, so it is cleared. Clearing is done by the Library in `update_style`, not by the page.
- **Snapshots per try.** A job stores the text and song it ran with. The comparison says "used the style's text and song unchanged" by comparing the reproduction with the style and the reference, not by trusting the page.
- **Omitted shots carry no timing.** A shot left out of a video shows a dash. A guessed length would make the cut check look better than it is.
- **Unmeasured cuts are never a pass.** Rows with no measured cut stay "-" and are counted in the worst-error line.
- **Play both is event-driven.** Our own pause calls are counted so they do not pause the other video again, and a start in progress ignores the stalled "waiting" event.
- **Chromium-compatible test media.** The stored synthetic video is served as VP8/WebM with byte ranges, because Chromium will not seek without a 206 answer and could not play the first MP4.

## Bugs found

- **Stale reference after a song or frame rate change (story review, blocking).** Text T, song A, Try 1 set as reference. Switch to song B and try again: the reference stays. A reproduction then uses song B, `same_song` was true against the style, and the page said "unchanged" while the reference was cut to song A. `set_reference` also accepted a job made with another song. Fixed as described above, with contract and e2e tests.
- **Reproduction of another style (story review, minor, fixed).** `get_reproduction` returned a comparison for any finished job, including a plain try or another style's job. It now returns 409 unless the job is a reproduction of this style.
- **Unmeasured cuts looked like a pass (story review, minor, fixed).** With only some cuts detected, the worst error was the largest measured one with no hint of the others.
- **Stale reference note (story review, minor, fixed).** If the PUT cleared the reference and the next job POST failed, "Try N is now the reference" stayed on screen. The note is cleared right after the PUT succeeds.
- **Longer video stopped early (story review, minor, fixed).** The shorter video's pause event fired before `ended` and paused the longer one. Pause events are ignored once a video has ended.
- **Playback races found against real media (subtask 3).** The stalled "waiting" event during start paused both videos and lost the restart, and the queued pause events from our own pause calls paused them again. Both fixed, with a repeat-start test.
- **Gate failures on subtask 1.** Chromium could not play the synthetic MP4 (NotSupportedError), and "Save style" went to a `/styles` page that does not exist. Test media was transcoded to VP8/WebM, and Save now goes to the real Styles route with the heading checked.
