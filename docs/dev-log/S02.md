# S02 dev log: Only people with the demo passphrase can use the app, and secrets never reach the logs

## Summary

S02 puts one shared demo passphrase in front of the whole app and makes sure secrets never reach a log.

It builds:
- Access: a pure ASGI middleware that checks HTTP basic auth (any user name, password = `DEMO_PASSPHRASE`) on every route except `GET /healthz`;
- Scrubbing (system-wide contract): a process-wide log record factory that removes the OpenRouter key, the passphrase, bucket secrets, Basic/Bearer tokens, presigned URLs and base64 image data from every log record.

Kind: module. Size: M. Blocked by: S01. Review gate: agents. Supports FR-3.2 (shown in S20). Guards GC-3.

**Status:** landed by agents. The full gate (`bash scripts/gate.sh`) passed with 171 tests and ruff clean. No human demo is needed for this story (review gate: agents). `DEMO_PASSPHRASE` must be set on Railway before deploy (see Follow-ups).

## What was built

Production code stays in `app/access/` plus a hook in `app/__init__.py`. `app/main.py`, `app/config.py` and `tests/conftest.py` are untouched. No new dependency.

- `app/access/__init__.py`: `PassphraseMiddleware` (pure ASGI, no blocking I/O, `lifespan` passes through) added by `install(app)`.
  - Only the exact path `/healthz` is open. `/static`, `/docs`, `/openapi.json` and unknown paths are protected because the middleware wraps routing.
  - The `Authorization` header must use the `basic` scheme (case-insensitive). Base64 and UTF-8 decoding are strict, and any error refuses. The split is on the first `:`. The password is compared with `hmac.compare_digest` against `DEMO_PASSPHRASE`, read per request.
  - A refusal is a 401 with an empty body and `WWW-Authenticate: Basic realm="AutoHDR demo", charset="UTF-8"`.
- `app/access/scrubbing.py`: `scrub(text)` and `install_log_scrubbing()`.
  - Rules, in order: literal settings secrets (OpenRouter key, passphrase, bucket secret and key id, length >= 4), data URIs, presigned URLs and bare signed query parameters, `sk-or-`/`sk-` keys, Basic/Bearer tokens, bare base64 of 100+ characters.
  - The record factory is idempotent. It scrubs `msg`, `args` (element-wise, keeping tuple and mapping shape so the `uvicorn.access` 5-tuple still formats), `exc_text` and `stack_info`. It covers every logger (app, uvicorn, httpx, botocore) and every handler, including pytest's caplog.
  - The `app` logger gets an INFO stderr handler that resolves `sys.stderr` at emit time.
  - If scrubbing fails, the line is withheld rather than leaked.
- `app/__init__.py`: installs scrubbing on import, so the web process, the worker and the CLIs are all covered.
- Tests: `tests/access/test_passphrase.py` (13 tests), `tests/access/test_scrubbing.py` (10 tests).
- Shared test support: `tests/support/fixtures.py` (`DEMO_PASSPHRASE`, `DEMO_AUTH`, the `client` fixture sets the env and auth, new `serve()` context manager used by `live_server`); `tests/app/test_blocking.py` (one `auth=`); `tests/e2e/conftest.py` (Playwright `http_credentials`); `.env.example` (one comment line, value stays empty).

## Key decisions and assumptions

- Fail closed: an empty `DEMO_PASSPHRASE` refuses every route except `/healthz`. The Must hold "no route but /healthz answers without it" wins over local convenience. Assumption recorded in the plan.
- The 401 body is empty. The Access contract's "no body detail" overrides the JSON error format for this one response.
- Pure ASGI middleware instead of `BaseHTTPMiddleware`, per the Blocking work contract.
- Scrubbing at record creation (`logging.setLogRecordFactory`), not in handlers or formatters, so third-party loggers and caplog are covered. Records' `extra` fields are not scrubbed; later stories must not put secrets in `extra`.
- Additions beyond the plan, disclosed by the implementer: bare signed query parameters are redacted (covers relative paths in uvicorn access lines); a record that fails to scrub is withheld.
- Tests use synthetic, hand-written key, presigned URL and an in-memory Pillow PNG. Credentials are never put in a URL's userinfo (httpx logs URLs).
- PRD versus docs: the PRD does not mention login, accounts, passwords, access control or logging. REQUIREMENTS FR-3.2 ("no accounts, one shared demo passphrase") and the ARCHITECTURE Access and Scrubbing contracts govern. No place where the PRD overrode the docs or the wireframe.
