# S07 dev log: The app can generate a clip from a photo with Veo 3.1, or Seedance as a fallback

## Summary

S07 builds the video half of the Providers interface: `generateClip`, `allowedLengths` and `recoverCalls`. A shot's clip is asked for from OpenRouter's Videos API at 1080p, 16:9, with no audio and the photo as the first frame. The call waits for the job, downloads the clip with the key header, and records its seconds and cost in `provider_calls`. Under BYOK the cost is seconds times the listed price per second. A clip left running when the worker restarts is collected into the bucket at the next start. FakeProviders makes a short, real, playable clip with error injection.

Requirements: CO-1, DE-5. Supports: FR-1.4 (shown in S22). Guards: RL-1, CO-1, DE-5. Kind: module. Size: L. Blocked by: S01. Review gate: agents. Not in this story: choosing the fallback model for a shot (S28).

## What was built

New files, all under `app/providers/` except the tests:

- `clip_calls.py`: the `provider_calls` write path for clip calls: `now_utc`, `start`, `set_request_id` (committed at once, so recovery can find the job), `record_cost` (never lowers a cost already on the row), `finish_ok`, `finish_error` (message scrubbed and cut to 500 characters), `open_clip_calls`.
- `video_api.py`: the Videos API client pieces: a `TRANSPORT` hook for tests, the auth header, the error mapping (429 `rate_limited` with `Retry-After`, 402 `out_of_credit`, 403 or moderation reasons `refused`, 408 `timeout`, other `failed`), the cached model list (`allowed_lengths`, `price_per_second`), `resolution_for`, `poll_job`, `download`, `clip_cost`, `configured_price`, and the helpers `is_permanent_download_error` and `clip_lost`.
- `video.py`: `generate_clip`: opens the row, POSTs `/videos`, saves the request id, polls to a terminal status or `CLIP_TIMEOUT_S`, computes the cost, downloads, and closes the row. One HTTP request per step, never a retry.
- `video_recovery.py`: `recover_calls`: collects clips left running (download, `Files.put`, probe, cost, close), keeps polling still-running jobs in a daemon thread, and never raises out of worker start.
- `fake_video.py`: the fake clip (a real ffmpeg 1920x1080 test pattern, no audio, made at run time), `fail_on` error injection, `allowed_lengths`.
- Delegating bodies only in `app/providers/openrouter.py` (`generate_clip`, `allowed_lengths`, `recover_calls`) and `app/providers/fake.py` (`generate_clip`, `allowed_lengths`), through function-local imports.
- New settings `VIDEO_LIST_PRICES` (default `google/veo-3.1=0.20`) and `CLIP_COLLECT_WINDOW_HOURS` (default 24), added to `app/config.py`, `.env.example`, `tests/config/test_env_example.py` and the Configuration list in `docs/ARCHITECTURE.md`.
- Tests in `tests/providers/video/`: `conftest.py` (a `videos_api` fixture on `httpx.MockTransport`), `test_fake_clip.py`, `test_allowed_lengths.py`, `test_generate_clip.py`, `test_recover_calls.py`, `test_openrouter_wiring.py`. 42 tests in the directory at the end.

## Key decisions and assumptions

- **Separate write path.** S06's `calls.py` had not landed on the base when S07 was planned, so S07 wrote clip rows through its own `clip_calls.py` with the same row semantics and did not touch `calls.py`, `chat.py`, `errors.py`, `interface.py` or `models.py`. Folding the two write paths together is left for later (see follow-ups).
- **Cost.** `usage.cost` with source `reported`. Under BYOK (`usage.is_byok` true, else the model is in `BYOK_MODELS`), seconds times the per-second price from `GET /videos/models`, source `list_price`. This settles the BYOK part of ARCHITECTURE open question 7 for video. If the list cannot be read, the configured `VIDEO_LIST_PRICES` price is used, still `list_price`; 0.0 with a warning only when neither has a price (Seedance 2.0 is priced per video token, not per second, and is not in `BYOK_MODELS` by default).
- **Seconds.** `ClipResult.seconds` and `output_seconds` are the requested length, because `Media.probe` was not built when the code was written. Recovery probes, falling back to the stored seconds.
- **No retry.** Every step is one HTTP request. A 402 or 429 makes no second request, and the row is closed before the error reaches the caller (RL-1). Re-downloading a finished job during recovery is collection of a clip already paid for, not a second paid call.
- **Key handling.** The key goes only in the `Authorization` header to the base-URL host. The content URL from `unsigned_urls` is used only when its host equals the base host. Messages go through `scrub` and are cut to 500 characters; transport errors are reported by type name only; the log line carries model, status and error kind only.
- **Recovered clips** go to bucket key `clips/recovered/<provider_call id>.mp4` and are kept, not reused (A-8).
- **A clip that finished but cannot be downloaded** keeps its recorded cost. It is retried while inside the collect window, and closed as error `failed` ("The clip finished but could not be downloaded.") on a permanent 403, 404 or 410, or when the window (24 h from `started_at`) has run out.
- **PRD versus docs.** No place was found where the PRD overrode the docs or the wireframe. The PRD has nothing on the video provider beyond prompt tips tuned for another model; its choice does not conflict with Veo 3.1 or Seedance in STACK.md. STACK.md was the source for the Veo 3.1 list price ($0.20 per second).

## Found late and follow-ups

- **Live clip not run.** The one live 4 s Veo 3.1 clip from a synthetic image (paid, by hand) has no recorded result. The orchestrator should run it and add the result. It will also confirm the Videos API's 402, 429 and `Retry-After` behaviour, the shape of a failed job's `error`, and any moderation marker, none of which are documented (ARCHITECTURE open question 7).
- **Two write paths.** `clip_calls.py` duplicates S06's `calls.py`, which has since landed. Fold the clip rows into `calls.py` (with a cost argument on `finish_error`) and merge the fake's `fail_on` with S06's.
- **Seedance under BYOK.** Seedance 2.0 is priced per video token, so a BYOK Seedance clip records 0.0 `list_price` with a warning. Add a per-second estimate or accept it.
- **Recovery robustness (minor).** An unknown poll status closes a recovered row but keeps `generate_clip` polling (share one terminal-status tuple). One transient poll error still closes a known-completed row for good (its cost is kept). A job that completes after `generate_clip` timed out is never collected. The collect window is checked only when `recover_calls` runs (startup and the background pass). If the HTTP client cannot be created in the background thread, its rows are closed as failed instead of left for the next restart.
- **Small items (minor).** `leave_open` and `http_status` are dynamic attributes on `ProviderError`, set to avoid editing S06's `errors.py`; make them explicit fields later. `_DONE` in `video_recovery.py` is a module-level set that only grows. `_content_url` checks the host but not the scheme. `Retry-After` accepts `inf`, `nan` and negative values, and so does a configured `VIDEO_LIST_PRICES` value. A failed `os.unlink` inside `except BaseException` could replace the original error. Under BYOK, a probed length slightly below the requested one leaves `output_seconds` and cost slightly inconsistent. `fake_video.fail_on` accepts any string.
- **Seconds are the requested length** in `generate_clip`; once `Media.probe` is in use, a later story may switch to the probed length.
- **Flaky test outside this story.** `tests/deploy/test_processes.py::test_killing_one_process_stops_honcho_and_frees_the_port` failed twice during parallel runs and passed alone; it did not fail in the final gate runs.
